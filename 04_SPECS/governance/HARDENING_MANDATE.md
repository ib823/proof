### C1 — The proofs don't cover the compiler you run

> *"The proofs don't cover the compiler you run. Coq proves the rules are sound for a mathematical model. `riinac` is a separate Rust implementation of those rules. My tests show it enforces them well, but that is tested, not proven. CompCert and CakeML prove the compiler itself."*

**Elements.**
- C1.a: Coq proves soundness only of a mathematical model.
- C1.b: `riinac` is a separate Rust implementation with no formal link to that model.
- C1.c: Enforcement is tested, not proven.
- C1.d: The reference standard is a compiler whose own correctness is proven (CompCert, CakeML).

**Target end state.**
- There is a documented chain of trust from source text to executed behaviour:

  > parse → elaborate to core → type/effect/IFC check → evaluate or lower → emit C/WASM → C compiler → runtime/builtins

- Every link in that chain is in one of three states:
  - (i) proven,
  - (ii) validated on every compile against a Coq-verified artifact, or
  - (iii) explicitly listed in `TRUSTED_BASE.md` together with its test evidence.
- A program accepted in "assured mode" carries `PROVEN-IMPL` guarantees for type safety and effect soundness. It carries the same for non-interference when it lies in the fragment the NI theorem covers.
- The compiler reports per program exactly which guarantees apply.

**Standards.**

- **S1.1 — Normative core.**
  - The Coq definitions in `foundations/Syntax.v`, `Typing.v` and `Semantics.v` are the single normative definition of the core language.
  - Write `docs/spec/CORE_MAPPING.md`. It maps every Rust core-AST constructor (`03_PROTO/crates/riina-types/src/lib.rs`, `pub enum Expr`, `Ty`, effects, security levels) to its Coq constructor, and every surface construct to its elaboration.
  - Any surface construct without a core mapping must be rejected (R3).
  - **Must hit:** 100% of Rust `Expr`/`Ty` variants and 100% of Coq `expr`/`ty` constructors appear in the mapping. A generated test fails CI when a variant is added on either side without updating the mapping.
- **S1.2 — Elaboration output.**
  - Add `riinac emit-core <file.rii>`. It prints the elaborated core term in a format the S1.3 oracle reads. Use an S-expression that matches Coq constructor names one-to-one.
  - Output must be deterministic, and pretty-print → parse must round-trip.
  - **Must hit:** emit-core succeeds on 100% of programs that pass `check`, and the round-trip test passes on all of them.
- **S1.3 — Verified oracle.**
  - In `02_FORMAL/extraction/`, use Coq `Extraction` to extract `type_check_fn` and `run_fn` (with every function they depend on) into a **dev/CI-only** tool, `riina-oracle`. It reads emit-core output and prints `{accepted, type, effect}` or `{value | stuck | out-of-fuel}`. Pin the extraction-target toolchain version.
  - The oracle is not a runtime dependency of `riinac`, so the zero-dependency policy for the shipped compiler stays intact.
  - **Must hit:** the oracle builds from a clean clone with one documented command on Linux, macOS and Windows.
  - **Must hit:** `type_check_fn_sound` is stated against the **same** `has_type` relation that `TypeSafety.type_safety`, `EffectGate.effect_sound_multi_step_declared` and `NonInterferenceRefFree.ref_free_noninterference` use. Prove this with a Coq `Check`/`Print` audit committed as a test.
- **S1.4 — Differential conformance** (the security gate). For every program P:
  - If `riinac` accepts P with type T and effect ε while the oracle rejects `emit-core(P)`, that is a **P0 soundness bug**. It blocks merge and release.
  - If `riinac` rejects P and the oracle accepts it, that is a completeness gap (P2) and gets tracked.
  - The corpus is:
    - every `07_EXAMPLES` file
    - every `riinac` test fixture
    - every `.rii` snippet in docs
    - a **type-directed random program generator** plus a mutation fuzzer, producing ≥ 30% ill-typed programs and ≥ 20% programs that violate IFC or effects, and covering 100% of core constructors (measured)

  **Must hit:**
  - ≥ 10,000 generated programs on every PR.
  - ≥ 1,000,000 nightly.
  - A release requires the last 7 nightlies clean.
  - **0 soundness discrepancies.**
  - Constructor coverage = 100%.
- **S1.5 — Semantic differential.**
  - For terminating programs, compare the Rust interpreter (`riinac run`), the C backend, the WASM backend (where supported) and the oracle's `run_fn`. Their results must be identical: value, stuck/error class, and output trace.
  - The existing backend differential is 26/30 byte-equal (REQ-27 note).
  - **Must hit:** 100% equality. Any exception must be listed with a written reason and a pinned test, and it can never involve a security-relevant result.
- **S1.6 — Assurance route** (**owner decision**; prepare `DEC-C1-route.md`).
  - Route A, *verified kernel gate* (recommended):
    - `riinac check --assured` and `riinac build --assured` run the extracted, Coq-verified `type_check_fn` on the emit-core term of every program, and refuse anything it rejects.
    - The Rust checker stays in place for error messages and speed.
    - The kernel ships as a separate pinned binary or library. Its toolchain goes in `TRUSTED_BASE.md`.
  - Route B, *kernel transliteration*: rewrite the Rust core checker as a line-by-line transliteration of the extracted code. Commit a correspondence document, and add an equivalence differential against the oracle (S1.4) that is permanent and runs in CI.
  - Route C, *verify the Rust*: prove the Rust checker refines `type_check_fn` using a Rust-to-proof tool (for example hax, Aeneas or coq-of-rust). This gives the highest assurance at the highest cost.
  - **Must hit:** one route is fully in place for type, effect and IFC checking. Until it is, no surface may say "proven before the code runs", "formally verified compiler" or anything equivalent about the shipped binary (see §5).
- **S1.7 — Completeness of the verified checker.**
  - Prove `type_check_fn_complete`: `has_type … -> type_check_fn … = Some …`, possibly up to subsumption.
  - If that's impossible, document precisely which typable terms the checker rejects.
  - **Must hit:** the theorem is closed, or `docs/spec/CHECKER_INCOMPLETENESS.md` lists every gap with a witness term.
- **S1.8 — Per-program guarantee report.**
  - `riinac check --json` must emit a `guarantees` object, for example: `{"type_safety":"PROVEN-MODEL|PROVEN-IMPL", "effect_soundness":…, "noninterference":"PROVEN-…|ENFORCED-TESTED", "termination":…, "constant_time":…, "fragment":"ref_free_fix_free|full"}`.
  - The fragment classifier must be a Coq-defined decidable predicate. Its decision procedure must be proven equal to the NI theorem's hypothesis, and then extracted or differentially tested.
  - **Must hit:** the report appears for 100% of accepted programs, and the classifier differential shows 0 discrepancies.
- **S1.9 — Parser.**
  - Write a normative EBNF grammar in `docs/spec/GRAMMAR.md`.
  - The grammar must have a conformance test suite.
  - Required properties: parse → pretty-print → parse yields an equal AST; `riinac fmt` is idempotent; the fuzzer finds no crash or hang.
  - **Must hit:** 0 crashes or hangs in 24 h of fuzzing per release, round-trip equality on 100% of the corpus, and grammar coverage ≥ 95% of productions exercised.
- **S1.10 — Backend and runtime.** For `emit-c` and the C runtime prelude (about 5,000 lines emitted into every binary):
  - (i) Specify each builtin in Coq: its effect, its security label, and its semantics where the model has them. Test the Rust and C implementations against that spec.

## 7. Session protocol

Use the master plan's Part 8 protocol (ORIENT → ASSESS → DECIDE → VERIFY BEFORE → EXECUTE → VERIFY AFTER → UPDATE → HANDOFF) with these additions.

1. **ORIENT.** Read this mandate, `RIINA_MASTER_PLAN.md` (Part 2, Part 3, Part 11 Active Gate) and the latest handoff in `docs/sessions/`. Run `git status`; you must be on `main` or your assigned branch.
2. **ASSESS.** Re-verify the §3 baseline items that touch today's work. Choose the highest-priority unmet standard in the current milestone.
3. **DECIDE.** If the work touches an R7 gate, write or update the decision memo and **stop** to ask the owner. Don't implement ahead of the decision.
4. **VERIFY BEFORE.** Record the current values of the standard's must-hit metric.
5. **EXECUTE.** Make the smallest complete change. Spec first (R12). Fail closed (R3).
6. **VERIFY AFTER.** Re-run the metric. Run `riinac verify --fast`, plus `--full` before any push. Run the drift check.
7. **UPDATE.** Regenerate ledgers and metrics with scripts only. Update the REQ status in the master plan.
8. **HANDOFF.** Write `docs/sessions/<date>-<slug>.md` using the template below.

**Stop and ask the owner when:**
- any R7 item comes up
- a theorem statement in the registry would change
- more than 20 files would be deleted or demoted
- a soundness discrepancy (P0) is found (report it immediately, with a minimal reproducer)
- a standard here conflicts with the master plan
- you can't meet a must-hit and would need to relax it (never relax it yourself)

**Handoff template:**

```markdown
# Session <date> — <slug>
Standards advanced: S?.? (status: met / partial / blocked)
Concern elements closed: C?.? …
Before → after metrics: <metric>: <before> → <after>
Evidence: <command> → <key output lines>; commit <hash>
Claims changed: <surface>: "<old>" → "<new>" (owner approval: <ref> | pending)
New/updated decision memos: DEC-…
Discrepancies or regressions found: …
Risks / open questions for owner: …
Next highest-priority step: …
```
